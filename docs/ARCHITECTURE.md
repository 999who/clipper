# Архитектура clipper

clipper — локальная программа с интерфейсом командной строки. Из длинного видео
(ссылка YouTube или локальный файл) она выбирает интересные фрагменты и делает
из них вертикальные клипы 1080×1920 с субтитрами в стиле CapCut.

Моменты выбираются только по heatmap YouTube («Самые популярные фрагменты») или
по ключевым словам. LLM и облачные сервисы не используются. Сеть нужна только
для скачивания видео и для однократной загрузки модели Whisper.

## Принципы

1. **Ядро отделено от интерфейса.** Вся обработка лежит в `clipper/core/`. Ядро
   ничего не печатает и не импортирует `typer`/`rich` — это проверяет тест
   `tests/test_core_isolation.py`. CLI сейчас и TUI позже только собирают
   параметры и показывают события ядра.
2. **Один объект конфигурации.** Параметры запуска собираются в `Config` в
   таком порядке: значения по умолчанию → файл конфига → флаги. Флаги важнее всего.
3. **project.json — граница между анализом и рендером.** Анализ пишет фрагменты
   и слова с таймкодами, вы можете поправить файл руками, рендер читает его.
4. **Этапы независимы.** Каждый этап — функция «вход → выход», его результат
   кэшируется на диске. Сбой одного клипа или необязательного шага не ломает
   остальное.
5. **Никаких захардкоженных путей.** Все пути берутся из конфига (`paths.*`)
   или вычисляются относительно пакета: стили, шрифты, модели.

## Рабочие папки

Всё, что создаётся при работе, лежит вне репозитория. По умолчанию — относительно
текущей папки, пути задаются через `paths.workdir` и `paths.output`.

```
work/<id>/                  id = ID ролика на YouTube или имя файла
  source.mp4, info.json     скачанное видео и метаданные yt-dlp (локальный файл не копируется)
  source.json               итог этапа 1: путь к видео, параметры, heatmap
  audio16k.wav              звук для Whisper
  transcript.json           кэш распознавания
  project.json              ← этот файл правите вы
  clipper.log               команды ffmpeg и их вывод
  tmp/                      .ass, траектории лица и прочее временное
output/<id>/
  clip_01.mp4, clip_01.jpg, …
```

## Поток данных

```
analyze:  download → [кандидаты по heatmap] → transcribe → highlights → project.json
                                                                          ↓  ручная правка
render:   project.json → audio → timeline → subtitles → reframe → ffmpeg → output/<id>/clip_NN.mp4
```

В режиме `heatmap` кандидаты выбираются до распознавания, и Whisper обрабатывает
только их (±5 с). В режиме `keywords` распознаётся всё видео, а поиск идёт по
транскрипту.

## Ядро и интерфейс

- **API ядра** — обычные функции: `analyze(source, cfg, reporter) → Project`,
  `render(project, cfg, reporter)`, `run(...)`, `calibrate(...)`, `run_doctor(...)`.
- **События.** Ядро сообщает о ходе работы через `Reporter` (`core/events.py`),
  который отправляет события в переданный приёмник — любую функцию
  `callable(event)`:
  - `StageStarted(stage, title, total)`
  - `StageProgress(stage, done, total, message)`
  - `StageFinished(stage, ok, message)`
  - `Message(level, text)` — информация или предупреждение.

  CLI рисует события через rich (`console.py`). TUI будет передавать их в свои
  виджеты через `app.call_from_thread` — ядро при этом не меняется.
- **Отмена.** `CancelToken` проверяется между шагами и останавливает ffmpeg.
  Сейчас отмена — это Ctrl+C, в TUI будет кнопка «Отмена».
- **Логи.** В ядре нет `print`. Для отладки — `logging` (флаг `-v` и файл
  `work/<id>/clipper.log`). Для пользователя — события.
- **Ленивые импорты.** faster-whisper, mediapipe и OpenCV импортируются только
  внутри своих этапов. `render` не трогает CUDA, а сломанный mediapipe не мешает
  `analyze`.

## Конфигурация

- `Config` — dataclass с секциями `paths`, `download`, `transcribe`, `select`,
  `audio`, `subtitles`, `reframe`, `render` и словарём пресетов `layouts`.
- **Где ищется файл конфига:** `--config PATH` → переменная окружения
  `CLIPPER_CONFIG` → `./clipper.yaml`. Если файла нет, работают значения по
  умолчанию.
- **Пример конфига.** В репозитории лежит `clipper.example.yaml` со всеми
  параметрами и комментариями. `clipper config --init` копирует его в
  `clipper.yaml`. Сам `clipper.yaml` не хранится в git, поэтому обновления
  программы не конфликтуют с вашими правками.
- **Флаги.** У каждого флага нет своего значения по умолчанию. Поэтому флаг
  переопределяет параметр, только если вы его явно указали. Любой параметр можно
  задать и без отдельного флага: `--set section.key=value`, например
  `--set select.min_len=15` или `--set layouts.my_setup.webcam.x=1500`.
- **Проверка значений.** Ошибка всегда указывает файл и ключ:
  - неизвестный ключ — с подсказкой («`min_lenght` — возможно, `min_len`?»);
  - неверный тип или значение не из списка — со списком допустимых значений;
  - противоречие между параметрами (`min_len > max_len`).
- **Особенность YAML.** В YAML 1.1 запись `9:16` без кавычек читается как число
  556 (шестидесятеричная запись). Загрузчик clipper это отключает: `aspect: 9:16`
  работает и без кавычек.
- `clipper config` показывает итоговые параметры и файл, из которого они взяты.

## project.json

```json
{
  "version": 1,
  "source": { "input": "https://youtu.be/…", "video": "work/abc123/source.mp4",
              "duration": 754.3, "width": 1920, "height": 1080, "fps": 30 },
  "analysis": { "mode": "heatmap", "language": "ru" },
  "clips": [
    { "id": 1, "enabled": true,
      "start": "00:02:03.400", "end": "00:02:41.850",
      "score": 0.93, "reason": "пик heatmap",
      "words": [
        {"text": "Короче", "start": 123.52, "end": 123.90},
        {"text": "смотри,", "start": 123.95, "end": 124.30}
      ] }
  ]
}
```

- Границы клипа записаны как `ЧЧ:ММ:СС.мс`, чтобы их было удобно сверять с
  плеером. Можно писать и секунды.
- Время слов — секунды от начала исходного видео.
- `enabled: false` пропускает клип при рендере, удалять его не нужно.
- Слова хранятся внутри клипа с запасом ±5 с за его границами. Границы можно
  сдвигать в пределах этого запаса без повторного распознавания. Если сдвинуть
  дальше, render предупредит, что на этом участке нет субтитров.
- Каждое слово записано одной строкой. Если исправить `text`, изменятся
  субтитры. Если удалить строку, слово пропадёт из субтитров.
- Полный транскрипт хранится отдельно в кэше `transcript.json`, чтобы
  project.json оставался коротким.
- При загрузке файл проверяется. Битый JSON или `start ≥ end` дают понятную
  ошибку с номером строки или клипа.

## Решения по этапам

### 1. Загрузка (`download.py`)
- yt-dlp подключаю как библиотеку: так доступен прогресс (`progress_hooks`) и
  `info.json` с полем `heatmap` — 100 точек `{start_time, end_time, value 0…1}`.
- Формат по умолчанию — H.264 до `download.max_height` (1080) + AAC в mp4. Такое
  видео быстро декодируется и без проблем читается OpenCV.
- Для YouTube yt-dlp нужен JS-движок. Deno ставится pip-пакетом
  (`yt-dlp[default,deno]`), yt-dlp находит его сам.
- Для локального файла параметры берутся через ffprobe, heatmap у него нет.
- Для ссылки YouTube ID виден прямо в ссылке: если `work/<id>/source.json` и видео
  уже есть, повторный запуск не обращается к сети (`--force` — скачать заново).
- yt-dlp получает тот же ffmpeg, что выбрал clipper (`ffmpeg_location`), и найденный
  JS-движок (`js_runtimes`); `download.cookies_from_browser` — для роликов,
  где YouTube просит войти.

### 2. Распознавание (`transcribe.py`)
- faster-whisper `large-v3`, `device="cuda"`, `compute_type="float16"`,
  `word_timestamps=True`, язык — авто или `--lang`.
- VAD-фильтр и `condition_on_previous_text=False` уменьшают зацикливания.
- Фильтр типичных галлюцинаций Whisper на музыке и тишине: «Продолжение
  следует…», «Субтитры сделал DimaTorzok» и подобных.
- В режиме heatmap распознаются только окна ±`transcribe.margin` (5 с).
  Пересекающиеся окна объединяются, звук нарезается из одного `audio16k.wav`.
- Результат кэшируется в `transcript.json` вместе со списком распознанных отрезков
  (`ranges`) и параметрами (`settings`). Новая просьба дораспознаёт только
  недостающие куски; смена языка или версии параметров — распознаёт заново.
  Повторный analyze с другими ключевыми словами не запускает Whisper.
- Звук читается из `audio16k.wav` кусками (модуль `wave`), без загрузки всего
  файла в память. Язык определяется на первом отрезке и дальше фиксируется.
- Движок подменяемый (`engine_factory`): тесты проверяют логику на фальшивом
  Whisper без GPU и без скачивания модели.
- **Видеопамять 12 ГБ.** Модели в float16 нужно ~4,5 ГБ, так что запас большой.
  Для распознавания всего видео (режим keywords) можно включить пакетный режим
  faster-whisper — это заметно быстрее. Если видеопамять занята игрой, есть
  запасной `compute_type: int8_float16`: та же модель, но ~3 ГБ.
- На Windows перед импортом ctranslate2 в путь поиска DLL добавляются папки
  `site-packages/nvidia/{cublas,cudnn,…}/bin` (см. раздел «Платформа»).

### 3. Выбор моментов (`highlights.py`, `pipeline.py`, `render.py`)
- **heatmap:**
  1. пики — локальные максимумы графика не ниже 30 % от самого высокого
     (сглаживать не нужно: YouTube отдаёт уже гладкую кривую). Первая точка
     пиком не считается — её завышают все, кто просто начал смотреть;
  2. окно вокруг пика расширяется в сторону более высокого соседа, пока
     «интерес» не ниже 60 % от пика и длина не больше `max_len`;
  3. если окно вышло короче `min_len` (узкий пик) или одна точка графика длиннее
     `max_len` (длинное видео), клип берётся средней длины `(min_len+max_len)/2`,
     а пик ставится на 40 % от начала — до него контекст, после реакция;
  4. окна ближе 5 с объединяются, если влезают в `max_len`; берутся N лучших;
  5. если пиков меньше, чем `select.clips`, остальные клипы добираются из самых
     «горячих» точек графика, по убыванию интереса (причина — «heatmap 0.85»).
     Они не пересекаются с уже выбранными ближе 5 с. На длинном видео точка
     длиннее клипа, поэтому внутри неё может быть несколько окон подряд.
     Обычно это продолжение или начало тех же пиков. Меньше клипов, чем
     просили, бывает только на коротком видео — тогда предупреждение.

  Распознаются только окна ±`transcribe.margin`. Если heatmap нет — понятная
  ошибка с готовой командой для режима `keywords`.
- **keywords:** регистр не учитывается, `ё` считается как `е`, пунктуация
  игнорируется. Поддерживаются шаблоны вида `побед*` (любое окончание) и фразы
  из нескольких слов. Каждое попадание даёт окно: четверть длины до слова,
  четверть после. Попадания, которые влезают в `max_len`, собираются в один клип;
  клипы ранжируются по числу попаданий и разнообразию слов. Для этого режима
  распознаётся всё видео (результат кэшируется).
- **Подгонка границ.** Начало и конец клипа сдвигаются к границам фраз (точка или
  пауза от 0,3 с) в пределах 3 с. Если фразовой границы рядом нет — хотя бы за
  пределы слова: клип никогда не начинается и не кончается посреди слова. По
  краям добавляется запас (0,15 с до, 0,3 с после), не залезая в соседние слова.
  Слишком длинный клип обрезается по последнему влезающему концу фразы. Если
  после подгонки клипы пересеклись, остаётся лучший.
- **project.json** пишется в `work/<id>/`; прежний сохраняется как
  `project.prev.json`, чтобы ручные правки не пропали при повторном analyze.
  При чтении файл проверяется, ошибки — с номером строки или id клипа.
- **Нарезка** (`render.py`): пока кадр как в исходнике, H.264 + AAC, `-ss` перед
  `-i` (при перекодировании это точно до кадра). NVENC, если реально работает,
  иначе libx264. Ошибка одного клипа не останавливает остальные.

### 4. Звук (`audio.py`, `timeline.py`)
- Результат этапа — `ClipEdit`: `Timeline` (какие куски исходника остаются) и что
  вырезано. `Timeline.to_output` / `map_words` пересчитывают время исходника во
  время готового клипа — по ним сдвигаются субтитры (и позже траектория лица).
  План строится при рендере по флагам, `project.json` не меняется.
- **Паузы** (`--cut-pauses`), способ — `audio.pause_detect`:
  - `volume` — ffmpeg `silencedetect` на отрезке клипа: тише `audio.silence_db`
    дольше `audio.min_pause`;
  - `words` — промежутки между распознанными словами (для стримов: из-за игры и
    музыки настоящей тишины почти не бывает). Промежутки длиннее
    `audio.max_gap` (3 с) не режутся: это скорее смех, крик или игра, которые
    Whisper не записывает, чем пауза.

  Из найденной тишины вычитаются слова (тихое слово не режется). От паузы
  остаётся по 0,12 с с каждой стороны; пауза у края клипа режется до края.
  Кусков не больше 60 — иначе остаются самые короткие паузы.
- **Слова-паразиты** (`--remove-fillers`) — список `audio.fillers`, фразы тоже
  («как бы»). Сравнение без учёта повторов букв и дефисов: «Э-э-э» = «ээ».
  Вырезается слово с запасом 0,04 с, не залезая в соседние слова.
  Whisper часто сам выбрасывает «эм»/«ээ»; `transcribe.verbatim`
  (`analyze --verbatim`) добавляет подсказку-«затравку» с паразитами. Это
  часть ключа кэша распознавания — после смены распознаётся заново.
- Если вырезано почти всё (осталось меньше секунды), клип рендерится без вырезок.
- Если по громкости пауз не нашлось, `quietest_level` декодирует звук клипа
  (8 кГц, моно) и находит самый тихий отрезок длиной `min_pause` — по нему
  выводится подсказка с порогом `--silence-db`. Клип короче `select.min_len`
  после вырезок — предупреждение.
- Whisper по-русски отдаёт «Ха -ха», «кто -то» отдельными словами — они
  склеиваются при распознавании и при чтении кэша (`join_hyphenated`).
- **Рендер:** `trim`/`atrim` по кускам через `split`, фейды звука 10 мс на
  стыках, `concat`. Звук и видео остаются синхронными (проверяет тест).

### 5. Субтитры (`subtitles.py`)
- pysubs2 генерирует `.ass` на каждый клип (`work/<id>/tmp/clip_NN.ass`); размер
  холста (PlayRes) равен размеру выходного кадра. Время слов — после вырезок
  этапа 4 (`Timeline.map_words`).
- **Строки.** На экране 1–`max_words` слов (стиль, `subtitles.max_words`,
  `--max-words`). Новая строка — после конца предложения (`.!?…:;`, отдельное
  «—»), после паузы ≥ `pause` и когда строка длиннее `max_chars`. Строка держится
  `hold` после последнего слова; промежуток между строками короче 0,25 с не
  показывается пустым экраном.
- **Подсветка.** На каждое слово — событие со всей строкой: текущее слово
  цвета `highlight` и «выпрыгивает» (`\fscx/\fscy` + два `\t`: `pop_from` →
  `pop_peak` → 100 % за `pop_duration`). Позиция — `\an5\pos(центр, position × высота)`.
- **Текст.** КАПС без пунктуации, дефис внутри слова остаётся («КАК-ТО»).
  Разбитые по дефису слова Whisper («Ха» «-ха») склеиваются и здесь — для
  старых project.json.
- **Ширина.** Ширина строки оценивается по ширине букв Montserrat Black
  (1 em = 0,634 × размер шрифта в libass, замерено). Не влезает — `\fs`
  уменьшается до 70 %; дальше переносит libass (поля `margin`).
- **Стиль** — `styles/capcut.yaml`, значения совпадают с dataclass `Style`
  (проверяет тест). Свой файл можно сократить до изменённых строк. Размеры — для
  кадра 1080×1920, масштаб — `min(ширина/1080, высота/1920)`. Цвета — `"#RRGGBB"`.
  Ошибки в стиле — `ConfigError` с подсказкой (неизвестный ключ, цвет без кавычек).
- **Шрифты.** Montserrat Black + OFL.txt лежат в `clipper/fonts/`; вместе с
  `font_file` стиля они копируются в `work/<id>/tmp/fonts/`, и ffmpeg получает
  `fontsdir=fonts`. Системные шрифты libass тоже находит.
- **Рендер.** `subtitles=filename=clip_NN.ass:fontsdir=fonts` — после склейки
  кусков (или сразу после входа, если вырезок нет). ffmpeg запускается из
  `work/<id>/tmp`, поэтому в фильтре только относительные пути — на Windows не
  нужно экранировать `C:`. Нет libass (нет фильтра `subtitles`) — предупреждение,
  клипы без субтитров. Нет слов в клипе — клип без субтитров.

### 6. Кадрирование и рендер (`reframe.py`, `facetrack.py`, `render.py`, `calibrate.py`)
- **Выход** — всегда 1080×1920. Граф ffmpeg одного клипа:
  `вход → [trim/concat вырезок] → кадр (reframe) → subtitles → H.264 + AAC`.
  Субтитры рисуются уже на кадре 1080×1920.
- **Режим `video`** (`reframe.py` — чистая геометрия и строки фильтров):
  - окно — самое большое с нужным отношением сторон внутри кадра (9:16 из 16:9 —
    608×1080), стороны чётные;
  - `9:16` — окно растягивается на весь кадр;
  - `1:1` и `original` вписываются по ширине. Фон `blur` — копия видео, уменьшенная
    до 270×480, `boxblur` и обратно 1080×1920 (в разы быстрее, чем размывать
    полный кадр); `black` — `pad`.
- **Слежение за лицом** (`facetrack.py`, `--crop face`):
  - Кадры клипа — 5 раз в секунду, ширина 960 (ffmpeg → rawvideo → numpy).
  - Детектор — `reframe.detector`:
    - `yunet` (по умолчанию) — `cv2.FaceDetectorYN`, модель YuNet (230 КБ, MIT) в
      `clipper/assets`, ~15 мс на кадр;
    - `mediapipe` — BlazeFace short-range через Tasks API (Apache 2.0). Модель для
      селфи: на кадре 960×540 не видит лиц меньше ~15 % высоты. Поэтому кадр ещё
      режется на плитки по полвысоты с перекрытием, результаты сводятся (NMS).

    Замер на кадре 1920×1080: YuNet находит лицо высотой ~60 px, BlazeFace даже с
    плитками — только от ~95 px. Поэтому по умолчанию YuNet. Обе модели читаются
    из памяти: OpenCV на Windows не открывает пути с кириллицей.
  - Смена сцены — средняя разница миниатюр 32×18 в HSV > 30 (как в PySceneDetect).
  - Траектория (`camera_path`, чистая функция):
    - главное лицо — самое крупное, но прежнее остаётся, если рядом и не меньше
      половины крупного;
    - мёртвая зона 12 % ширины окна;
    - лицо пропало — ждём 1 с, потом цель — центр;
    - сглаживание — два прохода скользящего среднего по 1 с, отдельно в каждой сцене;
    - лицо меньше чем в 20 % кадров — окно по центру.
  - Траектория пересчитывается во время готового клипа (`Timeline.to_source`) и
    пишется в `tmp/clip_NN.cmd`: `sendcmd` шлёт `crop@face x/y` на каждом кадре,
    где окно сдвинулось. Весь клип — один запуск ffmpeg.
  - Найденные лица кэшируются в `tmp/faces_NN.json` (ключ: видео, границы,
    детектор). Если детектор не загрузился — предупреждение и окно по центру.
- **Режим `stream`** (`--layout <имя>`):
  - Вебка вырезается по координатам из пресета и масштабируется так, чтобы
    заполнить верхнюю зону (`webcam_zone`) без искажения пропорций.
  - Игра обрезается под нижнюю зону (`game_crop`: center/left/right), затем зоны
    склеиваются через `vstack`. Высоты зон чётные и в сумме дают ровно 1920.
  - `source_size` — разрешение кадра, по которому сняты координаты. Если видео
    окажется в другом разрешении, координаты пересчитаются пропорционально.
- **`clipper calibrate SRC`** сохраняет `work/<id>/calibrate.png` (`--at 1:30`, по
  умолчанию 1:00) с координатной сеткой: линии через 50 px, подписи через 100 px.
  С `--layout NAME` дорисовывает рамку вебки и окна игры и сохраняет
  `calibrate_<NAME>.png` — итоговый кадр 1080×1920 через тот же `stream_graph`, что
  и рендер. PNG пишутся через `cv2.imencode`: `imwrite` на Windows не умеет
  кириллицу в путях.
- **Кодирование:** H.264 + AAC, `yuv420p`, `+faststart`. `--encoder auto`
  выбирает NVENC, если тестовое кодирование прошло, иначе libx264.

### 7. Дополнительно
- `--out` задаёт папку вывода: клипы лежат в `<out>/<id>/`. Папка запоминается в
  `project.json` (поле `output`). Порядок: `--out` (или выбор в TUI) → `output`
  проекта → `paths.output`. У `analyze` и `run` `--out` сразу пишется в проект.
- Обложки `clip_NN.jpg` и склейка клипов в один ролик были, но убраны по
  решению пользователя. Старые ключи `render.thumbnails` и `render.concat` в
  `clipper.yaml` дают понятную ошибку с подсказкой (`config.REMOVED_KEYS`).

## Платформа и зависимости

- **Python 3.10+.** Проверено на 3.14.7: для Windows x64 под CPython 3.14 есть
  готовые колёса всех зависимостей, включая ctranslate2, onnxruntime, av,
  mediapipe (использует ctypes, от версии Python не зависит) и opencv (abi3).
- **CUDA на Windows.**
  - ctranslate2 4.5+ во время работы загружает `cublas64_12.dll` и
    `cudnn_*64_9.dll`. Их поставляют пакеты `nvidia-cublas-cu12` и
    `nvidia-cudnn-cu12` (9.x), которые ставятся только на Windows (маркер в
    pyproject).
  - Сами Python и ctranslate2 эти DLL не находят. Поэтому `env.setup_cuda_dlls()`
    добавляет папки `site-packages/nvidia/*/bin` в путь поиска DLL и в `PATH`.
  - Если CUDA 12 и cuDNN 9 уже стоят в системе, пакеты можно удалить — DLL
    найдутся через `PATH`.
- **Выбор ffmpeg.** Ищется только в PATH (текущая папка не просматривается), перебираются все найденные сборки в порядке PATH. Берётся первая, у которой в `ffmpeg -buildconf` есть `--enable-libass`; если такой нет — первая по PATH. `ffprobe` берётся из той же папки. `clipper doctor` показывает пропущенные сборки без libass.
- **OpenCV.** Ставится только `opencv-contrib-python` — его требует mediapipe.
  Отдельный `opencv-python` конфликтовал бы с ним: оба пишут в модуль `cv2`.
- **mediapipe 1.0.** Устаревшего `mp.solutions` больше нет, используется только
  Tasks API.
- **yt-dlp.** YouTube часто меняется, и yt-dlp приходится обновлять:
  `pip install -U "yt-dlp[default,deno]"`. `clipper doctor` предупреждает,
  если версия старше 60 дней.
- **LLM-пакетов в проекте нет.**

## Ошибки и независимость этапов

- Ошибка для пользователя — `ClipperError(message, hint)`: что случилось и что
  сделать. CLI показывает её без трейсбека, трейсбек выводится только с `-v`.
- Результаты этапов кэшируются в `work/<id>/`. После сбоя повторный запуск
  продолжит с того же места. Флаг `--force` пересчитывает всё заново.
- Ошибка в одном клипе не останавливает остальные, в конце выводится сводка.
- Необязательные шаги при сбое не прерывают работу, а выдают предупреждение
  (лицо не найдено → кроп по центру).
- Файлы сначала пишутся во временный файл, затем переименовываются. Прерванный
  рендер не оставит битых mp4, а сбой не испортит project.json.

## Тестирование

`pytest` проверяет чистую логику без GPU, сети и видео:
- конфиг;
- события;
- поиск пиков heatmap;
- подгонку границ;
- ключевые слова;
- пересчёт времени;
- генерацию `.ass`;
- геометрию кадра.

Там, где нужен ffmpeg, тесты работают на коротких видео, сгенерированных через
`lavfi`. Если ffmpeg нет, такие тесты пропускаются.

## TUI (`clipper` или `clipper tui`)

Интерфейс в терминале на Textual поверх того же ядра. `clipper` без аргументов
запускает именно его. Всё делается стрелками
и Enter, без команд. Ядро не менялось, кроме двух функций для экранов:
`pipeline.list_projects` и `pipeline.save_edited_project`.

```
clipper/tui/
├─ __init__.py     run_tui: конфиг → приложение; stderr нативных библиотек → work/clipper-tui.log
├─ app.py          ClipperApp: стек экранов, выход с остановкой задачи
├─ settings.py     описание настроек форм (Setting/Section), SettingsStore, «то же в командной строке»
├─ widgets.py      SettingsList (Enter — изменить), ChoiceModal, InputModal, MenuModal, heatmap_text
├─ progress.py     ProgressScreen: задача ядра в потоке, этапы, лог, отмена
├─ project.py      ProjectScreen (клипы), ClipModal (границы, вкл/выкл)
├─ stream.py       режим стримера: PresetsScreen, PresetScreen (вебка, превью, сохранение)
├─ screens.py      Home, Projects, Analyze, Render, Results, Doctor
├─ system.py       открыть файл или папку программой по умолчанию
└─ clipper.tcss    стили
```

- **Экраны.**
  - Главное меню: новое видео, продолжить последний проект, все проекты,
    проверка окружения.
  - «Новое видео» — форма `analyze` (первой строкой — папка для клипов), дальше
    прогресс, потом экран проекта. Папка выбирается окном `FolderModal`:
    «▸ папка» — войти, «↑ Наверх», «＋ Новая папка…», путь вручную, диски в
    Windows (`os.listdrives`). Она пишется в `project.json` (`output`), и при
    открытии проекта TUI подставляет её в форму рендера.
  - Проект: полоса heatmap с отметками клипов, таблица клипов, текст выбранного.
    Enter — окно клипа (вкл/выкл, начало и конец вводом или сдвигом на ±1 с),
    пробел — вкл/выкл, `s` — сохранить, `r` — нарезать, `c` — «сколько клипов»:
    ввести число и найти моменты заново в том же видео (тот же режим и ключевые
    слова; язык и verbatim — из `transcript.json`, чтобы кэш распознавания
    подошёл). Горячие клавиши работают и в русской раскладке (`ы`, `к`, `щ`, `с`).
  - Рендер — форма настроек, дальше прогресс, потом результаты (Enter на клипе —
    открыть в плеере).
- **Режим стримера** (главное меню). Список пресетов из `layouts` и «＋ Новый
  пресет». Редактор: видео для примера (подставляется из последнего проекта),
  момент кадра, x/y/ширина/высота вебки, доля высоты под вебку, какую часть игры
  брать. «Кадр с сеткой» и «Превью клипа» вызывают `calibrate` (с несохранённым
  пресетом — параметр `layout`) и открывают PNG в системном просмотрщике;
  разрешение видео заполняется по кадру. «Сохранить» → `config.save_layout`:
  меняется только блок этого пресета в `clipper.yaml` (файла нет — создаётся из
  примера, прежний текст — в `clipper.yaml.bak`, после записи файл проверяется),
  затем `SettingsStore.reload` и в сессии включаются «Режим → стрим» и этот пресет.
- **Запуск без активации окружения** — `clipper.bat` в корне: переходит в папку
  проекта и запускает `.venv\Scripts\clipper.exe`.
- **Формы.** Каждая строка — параметр `Config`. Флаги и перечисления меняются
  выбором из списка, числа и текст — в окне ввода. Проверка — тем же
  `load_config`, что у флагов: неправильное значение не принимается, ошибка
  показывается в окне. Под формой — пояснение к выбранной строке и та же
  команда для CLI (только отличия от `clipper.yaml`).
- **Настройки** живут до выхода (`SettingsStore`: `clipper.yaml` + `--set` при
  запуске + выбранное в формах). В `clipper.yaml` TUI ничего не пишет, чтобы
  не потерять ваши комментарии.
- **Задачи** (`analyze`, `render`, doctor) идут в worker-потоке. События
  `Reporter` → `app.call_from_thread` → строки этапов с полосами прогресса и лог.
  Отмена — подтверждение, затем `CancelToken`, как Ctrl+C в CLI. Если были
  предупреждения, экран ждёт «Дальше →», чтобы их можно было прочитать.
- **Правка клипа** меняет только `project.json`, с копией в `project.prev.json`.
  Перед рендером несохранённые правки сохраняются: рендер читает файл с диска.
  Слова для новых границ берутся из `transcript.json`. Если часть клипа не
  распознавалась, TUI предупреждает, что там не будет субтитров.
- **Тесты** — `App.run_test()` без терминала: навигация, ввод и проверка значений,
  правка и сохранение проекта, рендер с подменённым ядром, ошибки и отмена.
